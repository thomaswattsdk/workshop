3 · What moves between territories

Git → Knowledge base · dated snapshots designedOne way. A snapshot is a record, not a copy: it carries a header (what, when, which commit, "not authority; the live version is in git") and is never loaded as an instruction.
Library or vault → git · read, then migrate on purposeReading informs. Nothing flows into git by itself. Moving a piece of logic is an explicit migration: copy into git, check it matches, then Thomas retires the original in Windows.
Project ↔ Workshop ↔ Claude OS · read across, write at homeAny session reads any repository. A change is committed in the repository it belongs to, saying where it came from. Only cross-cutting work leaves a handover in the OS.
The Map of Content, split by job designedThe Path Registry (where) lives in the Claude OS as the Map of Content. The library's own map, to be renamed Library Map (what is in it), stays in the library. No row is in both. Dated index snapshots of the library, taken before and after structural changes, show exactly what changed or went missing.
Why the shell never writes to the libraryThe sandbox mounts the Windows drive read-only, by design. Library writes go through the file editor, which the hook allows only in the zones above.

4 · How a lesson gets kept

The Difference Engine's loop, as it will run in Code.

  1. Friction in use. A task presses on a guide: it was wrong, missing, or not found. exists
  2. Say which of three outcomes it is: the core is wrong, the router mis-fired, or this is an edge, so the boundary extends. designed
  3. Capture in a git guide. An addition is applied and committed at once; a revision is proposed and waits for Thomas. designed
  4. Listed as "captured, not yet ticked". Thomas ticks it, or reverts it from git. to come
  5. At a milestone, a dated snapshot goes to the Code archive, headed as a record. designed
  6. The Observer checks from outside: it reads the hook's log and git after the session and flags any write outside its zone. to come
